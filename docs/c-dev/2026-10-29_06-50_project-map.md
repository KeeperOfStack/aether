# Project map: how the code becomes a running test

Status: verified 2026-10-29 against commit `da07f1d56` (full build run 40481584391) and the Windows artifact `Mumble_windows-2025.cl.x86_64`. Each fact names the file or log it came from. If a fact stops matching the code, fix this file in the same change.

## 1. Build options

| Option | Default | Set where | Effect |
|---|---|---|---|
| `client` | ON | `CMakeLists.txt:62` | Builds `mumble.exe` from `src/mumble/`. |
| `server` | ON | `CMakeLists.txt:63` | Builds `mumble-server.exe` (Murmur) from `src/murmur/`. |
| `packaging` | OFF | `CMakeLists.txt:64` | Builds the installers (CPack and WiX). |
| `tests` | follows `packaging` | `CMakeLists.txt:65` | Builds the test programs. |
| `sidecar` | OFF | `src/CMakeLists.txt:11` | Builds `mumble-screenshare.exe` from `src/sidecar/` (`src/CMakeLists.txt:249`). |

On Windows, `.github/workflows/build.sh` sets `-Dpackaging=ON` and `-Dsidecar=ON` (lines 44–45). Other platforms do not build the sidecar.

## 2. Build targets and where they land

- **`mumble`** (client): `src/mumble/CMakeLists.txt`. Only `mumble` has an install rule (lines 430–435). The client does not install the sidecar.
- **`mumble-server`** (Murmur): `src/murmur/CMakeLists.txt:56–58`. Built as a Windows GUI-subsystem executable.
- **`mumble-screenshare`** (sidecar): `src/sidecar/CMakeLists.txt`. It has **no install rule**, so the installers do not contain it.

## 3. What the CI artifact contains

The `Publish` step in `.github/workflows/build.yml` (around lines 143–155) uploads these paths: `build/mumble`, `build/Mumble.app`, `build/mumble-server`, `build/**/mumble*.msi`, `build/**/mumble*.exe`, `build/**/*.pdb`.

The Windows artifact `Mumble_windows-2025.cl.x86_64` (verified from the folder tree you pasted) contains:

- `mumble.exe`, `mumble-server.exe`, `mumble_ol_helper*.exe` and their `.pdb` files at the root
- `plugins/*.pdb`
- `installer/client/mumble_client-1.7.0-x64.msi` and `.exe`
- `installer/server/mumble_server-1.7.0-x64.msi` and `.exe`
- `src/sidecar/mumble-screenshare.exe`, which comes from the `build/**/mumble*.exe` rule and is **not** in the installers

So the sidecar is in the download but not in what you install.

## 4. Installers

- The client installer `mumble_client-1.7.0-x64.exe` is a WiX bundle. It installs the client MSI silently at `%ProgramData%\Package Cache` and registers the uninstall entry. The bundle log is `%TEMP%\Mumble_(client)_<timestamp>.log`.
- The version `1.7.x` comes from `project(mumble VERSION "1.7.${BUILD_NUMBER}")` in `CMakeLists.txt:20–21`.
- The only client-side change in the fork so far is the removal of the ASIO audio backend (commit `aa09160fc`). The client does not reference the sidecar (see section 5).

## 7. Known warnings

- `Connection: Failed to add flow to QOS` (`src/Connection.cpp:75`, inside `Connection::setToS`, which lines 66–75 show). It is logged when Windows refuses to add a QoS flow for a non-loopback connection. The connection still works. The DSCP marking it was meant to set is not applied. This matters for Phase 6 (network QoS). The server log showed it for a link-local IPv6 address.

## 8. The sidecar IPC test

`scripts/test_sidecar_ipc.ps1` starts `mumble-screenshare.exe`, connects to the pipe `mumble-sidecar-ipc`, and checks:

1. Hello with version 1 gets Welcome, then a Ready event.
2. ShareState On and Off do not close the pipe.
3. A new client can connect after the previous one leaves.
4. A wrong protocol version closes the pipe without Welcome.
5. An oversized frame closes the pipe.
6. The sidecar is still running and accepts a good client after the bad ones.

Run it with:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test_sidecar_ipc.ps1 -SidecarPath "<path to mumble-screenshare.exe>"
```

Result on the artifact build: 8 of 8 checks pass. ShareState does nothing yet, so checks 2 and 6 only show the sidecar does not crash.
